# Implementation Plan - AI Interview Preparation Assistant

This document outlines the design and step-by-step plan for building the **AI Interview Preparation Assistant**, a full-stack Generative AI application with a React frontend (Vite + shadcn + TailwindCSS v4), a FastAPI backend, and MongoDB as the database.

---

## Goal Description

The goal is to build an interactive AI Interview Preparation Assistant that allows users to:
1. Register, log in, and maintain a profile (education, skills, experience, target role).
2. Set up and start a mock interview for specific job roles (Python Developer, Java Developer, Data Analyst, Data Scientist, Machine Learning Engineer, AI Engineer) and interview types (Technical, HR, Behavioral).
3. Undergo a 5-question text-based mock interview, where each question is generated dynamically using Gemini, taking into account the candidate's profile, chosen settings, and prior questions.
4. Submit answers for real-time AI evaluation (scoring for technical correctness, communication, and relevance, plus feedback and weak-topic mapping).
5. View a final performance report with overall scores, identified weak topics, and a personalized improvement plan generated by Gemini.
6. Browse interview history to track progress over time.

## Proposed Changes

### Backend Setup

We will build the FastAPI backend inside the `backend` folder. We will reuse the existing `.venv` virtual environment and install the required dependencies.

#### requirements.txt
Defines all Python dependencies for the project.
- `fastapi` & `uvicorn` (web server)
- `pymongo` (MongoDB driver)
- `pydantic` & `pydantic-settings` (data validation and configuration)
- `google-generativeai` (Gemini API client)
- `python-dotenv` (environment variables)
- `passlib[bcrypt]` (password hashing)
- `pyjwt` (JSON Web Token creation/decryption)
- `python-multipart` (required for OAuth2 form logins)

#### config.py
Loads configuration variables (JWT keys, database URL, Gemini API Key) from `.env` and environment variables.

#### database.py
Initializes the MongoDB client and references collections (`users`, `interviews`, `questions_answers`, `results`).

#### models.py
Defines Pydantic models for request validation and response formatting (User, Interview, Q&A, and Result schemas).

#### auth.py
Provides utilities for password hashing (`pwd_context`), JWT encoding/decoding, and the FastAPI dependency to authenticate current users.

#### ai.py
Handles all LLM integration with the Gemini API:
- `generate_question(...)`: Dynamically generates a single interview question using context from previous questions to avoid repetition.
- `evaluate_answer(...)`: Evaluates a single answer using Gemini's structured output mode (JSON), rating relevance, communication, and technical correctness.
- `generate_improvement_plan(...)`: Generates weak-topic synthesis and actionable steps at the end of the interview.

#### auth_routes.py
Implements endpoints for registration, login, and retrieving the current user's profile.

#### profile_routes.py
Implements endpoints to get and update candidate profile details (education, skills, experience level, preferred role).

#### interview_routes.py
Implements interview lifecycle endpoints:
- `POST /interview/start`: Starts a new interview, saves metadata.
- `POST /interview/question`: Requests the next question (triggers Gemini call, saves question metadata).
- `POST /interview/answer`: Submits a candidate's answer, calls Gemini to evaluate, and returns the evaluation.
- `POST /interview/complete`: Calculates final averages, aggregates weak topics, generates the personalized improvement plan via Gemini, saves results, and updates the interview status to `completed`.

#### history_routes.py
Implements endpoints to fetch the history of completed interviews for the user and view specific interview reports.

#### main.py
Initializes the FastAPI application, configures CORS (to allow requests from the Vite frontend), and mounts all api routers.

### Frontend Setup

We will develop a highly premium web app using TailwindCSS v4 and shadcn components. 
We will use state-based navigation combined with a robust React state architecture. This ensures seamless session management during mock interviews.

#### AuthContext.tsx
Context provider that handles logging in, registering, storing JWT in localStorage, fetching/updating user profiles, and checking session validation.

#### Auth.tsx
A premium login and registration page featuring:
- Glassmorphic card design.
- Interactive toggle tabs (Login / Sign Up).
- Smooth hover animations and error validation.

#### Dashboard.tsx
The candidate landing portal:
- Welcoming layout displaying basic user information.
- Quick stats: Total interviews taken, average score.
- Direct links to start an interview or update profile.
- A list of recent interviews with quick links to view reports.

#### Profile.tsx
Candidate profile manager:
- Form fields for Education, Skills (with tag/chip inputs), Experience Level (Fresher, Mid, Senior), and Preferred Role.
- Interactive chip component to add/remove skills dynamically.

#### Setup.tsx
Interview configuration panel:
- Selection boxes for Job Role, Interview Type (Technical, HR, Behavioral), and Difficulty Level (Easy, Medium, Hard).
- Quick launch button that triggers `POST /interview/start`.

#### Interview.tsx
The live text-based mock interview screen:
- A progress tracker (e.g., "Question 2 of 5").
- A clear, readable question text area.
- Textarea input for answers with word counter.
- Loading/generating indicator (sleek skeletons or pulse loaders) while generating the next question/evaluating the answer.

#### Results.tsx
The comprehensive feedback summary:
- Circular visual gauges displaying Technical Knowledge, Communication, Relevance, and Overall scores.
- Expandable list of the 5 questions, displaying candidate's answers and individual AI evaluations.
- Detailed listing of "Weak Areas" (badge styling).
- Interactive, step-by-step "Personalized Improvement Plan".

#### History.tsx
The user's progress log:
- List of past interviews showing Date, Role, Type, and Overall Score.
- Search and filter options (by role/type).
- Detail view button to open the full Results page for any past interview.

#### App.tsx
We will rewrite `App.tsx` to handle page routing, global authentication context integration, and layout grids with global headers (Navbar).

#### Navbar.tsx
Modern navbar containing:
- Logo / Brand title.
- Link tabs (Dashboard, Profile, History).
- Logged-in user badge and Logout button.
- Clean glassmorphism styling.

## Verification Plan

### Automated / CLI Testing
- Verify backend dependencies install and app starts cleanly:
  ```powershell
  cd backend
  uvicorn app.main:app --reload
  ```
- Verify frontend starts cleanly:
  ```powershell
  cd frontend
  npm run dev
  ```

### Manual Verification
1. **Authentication**: Register a new user, log out, log back in, verify JWT storage.
2. **Profile Creation**: Set education, skills (e.g. Python, SQL), target role, and save. Verify updates persist on refresh.
3. **Setup**: Configure an "AI Engineer" Technical mock interview.
4. **Conduct Interview**: 
   - Verify 5 questions are generated one by one.
   - Type answers and verify submission loader works.
5. **Results Generation**: 
   - Complete the interview.
   - Verify circular progress indicators, scores, feedback comments, weak topics, and personalized plans render correctly.
6. **History**: Go to History page, verify the completed interview is logged, and click "View Details" to see the same results.
